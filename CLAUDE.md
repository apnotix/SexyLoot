# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project overview

SexyLoot is a World of Warcraft addon (pure Lua, no build step) for **World of Warcraft: Forever** (Interface `16001`, Classic-based client, see the sibling repo SexyInterrupter's CLAUDE.md). It replaces the loot window and the group-loot roll frames, shows roll results per player on the item, keeps a group loot feed, and lists the player's recent loot. All frames are positioned and configured through Edit Mode via the own embedded SexyEditMode-1.0 library (lib/SexyEditMode, source of truth: ../SexyEditMode).

There is no compiler, linter or test suite. Deploy by copying or symlinking this folder as `SexyLoot` into `Interface/AddOns/`, then `/reload`. `/sexyloot test` fills every window with sample data.

## Packaging / CI

- [.github/workflows/release.yml](.github/workflows/release.yml) runs on every push to `master`: bumps the patch number of `## Version:` in [SexyLoot.toc](SexyLoot.toc), commits and tags it (as `github-actions[bot]`, which does not retrigger the workflow), then runs `BigWigsMods/packager@v2` in the same job (tags pushed with `GITHUB_TOKEN` cannot start another workflow, so bump and package must share a job).
- [.pkgmeta](.pkgmeta) packages the folder as `SexyLoot`, uses `CHANGELOG.md` as the changelog and leaves out `CLAUDE.md`, both READMEs and `.github`.
- GitHub releases work out of the box. CurseForge needs `## X-Curse-Project-ID:` in the TOC plus the `CF_API_KEY` secret. WoWInterface needs `## X-WoWI-ID:` plus `WOWI_API_TOKEN`. Without them the packager skips that site.
- Keep the CHANGELOG entry for a release in `CHANGELOG.md` before pushing; the bump commit does not write to it.

## Forever client constraints (learned in SexyInterrupter)

- `## Interface: 120100, 16001` in one unified `.toc`; do not add per-flavor TOCs.
- **No `UIDropDownMenuTemplate`** frames from addons (blocked). Never use `RegisterDropdown`, `type = "select"` dropdown widgets or the native drop-down templates. Use checkboxes, sliders and buttons.
- **`COMBAT_LOG_EVENT_UNFILTERED` registration is blocked** on the beta; this addon does not use it. Loot and roll information comes from `CHAT_MSG_LOOT`, `START_LOOT_ROLL`, `CANCEL_LOOT_ROLL` and the `LOOT_*` events.
- `GetAddOnMetadata` / `C_AddOns.GetAddOnMetadata` are unreliable; do not call them at file-load time.
- XML `<Binding>` elements are rejected; no keybindings.

## Architecture

Load order (see [SexyLoot.toc](SexyLoot.toc)): LibStub, SexyEditMode, then `Locale.lua`, `Core.lua`, `RollFrames.lua`, `LootWindow.lua`, `Feed.lua`, `Winner.lua`, `FreeRolls.lua`, `MyLoot.lua`, `EditMode.lua`.

- **Locale.lua** provides `ns.T`. German is the source language: the key is the German text and comes back unchanged on deDE; every other client gets the English table in that file. Use `T["text"]` or `T("text %s", value)` for every user-visible string (Edit Mode labels included) and add the English text to `Locale.lua`. Prefer Blizzard globals (`NEED`, `GREED`, `PASS`, `LOOT`, `ITEM_BIND_ON_PICKUP`) where they exist, they are already localized.
- **Core.lua** defines `ns.defaults`, creates one invisible anchor frame per window (`ns.frames.roll/winner/freeroll/loot/feed/mine`), and on `ADDON_LOADED` builds `ns.cfg`, calls every module's `Init()`, then `ns.SetupEditMode()`, then `ns.Refresh(key)` for each window. `ns.Apply[key](cfg)` is how a module applies its settings.
- **RollFrames.lua** hides Blizzard's group loot frames (`UIParent:UnregisterEvent("START_LOOT_ROLL")` etc.), builds one row per roll and parses roll chat messages. Patterns are compiled from the `LOOT_ROLL_*` global strings (handles positional `%1$s` formats), so they work in every locale.
- **LootWindow.lua** unregisters `LootFrame` events and draws its own slot list. `GetLootSlotInfo` returns different argument orders on classic vs retail clients; the code detects which.
- **Feed.lua** owns `ns.ParseLoot` (loot chat messages). Self loot is forwarded to `ns.MyLoot:Add`. Roll winners are noted with `Feed:NoteWin` so the following "receives loot" line is not shown twice.
- **Winner.lua** shows the roll winner large mid-screen (`Winner:Display`, called from `RollFrames:Finish` and from the "won" chat branch without a row). Preview is sticky in Edit Mode.
- **Winner.lua** builds its soft glow as a 9-slice from `media/glow128.tga`. The textures in `media/` are generated by `tools/make_textures.py` (plain Python, no dependencies; `tools/` is excluded from the package). Only `glow128.tga` is still used; `fill64`, `ring64`, `mask64` and `glowicon64` are left over from the rounded card.
- **FreeRolls.lua** collects manual `/roll` results (system message `RANDOM_ROLL_RESULT`, compiled like the loot patterns). With at least two distinct players the list is shown, highest first; after `cfg.freeroll.hold` seconds without a roll it is cleared and hidden.
- **MyLoot.lua** stacks by item ID unless `noStack`, shows sell value via `GetItemInfo`.
- **Core.lua** also owns the look, modelled on SexyQuestHelper: `ns.FramedPanel(parent, title)` builds a window (dark brown fill, tooltip-style gold border via `BackdropTemplate` (`ns.BACKDROP`, content starts `ns.INSET` inside), optional title band, `f:SetBadge(text)` for the badge at the right of the band; `f.badgeInset` keeps room for a close button). `ns.HEAD` is the height of frame plus band, content starts below it. `ns.Pill` makes the coloured labels (`ns.TONES`: ok, warn, grey, lack, they), `ns.Button` the flat green button (`b.text` is its label). `ns.ApplyStyle` sets `panel.fill` (bg), `panel.accent` (frame colour) and the band alpha; never name a field `bar`, RollFrames and FreeRolls use it for their StatusBar. `ns.NineSlice` (used by Winner.lua for the glow) builds 9-slices from `media/`, `ns.FadeIn(frame)` is the shared fade-in. In RollFrames the rows are plain cards inside one framed window (`win`), and background and border colours are fixed defaults (`ns.defaults[key].bg/border`), not user options.
- **BagCleaner.lua** shows the "bags almost full" banner (anchor `ns.frames.bags`, settings `ns.cfg.bags`) and the clean-up dialog (`/sl bags`). It lists the cheapest items via `ns.ItemPrice(link, vendorPrice)` (returns price and whether it is an auction price), skips quest items, uncached items (price unknown) and items without price unless `showNoValue`, and destroys with a two-click confirm (`PickupContainerItem` + `DeleteCursorItem`, never in combat, only if the slot still holds the same link).
- **Disenchant.lua** lists disenchantable gear in the bags (`ns.cfg.disenchant`, `/sl de`). Each row has a SecureActionButtonTemplate macro button (`/cast Disenchant` + `/use bag slot`); secure frames can neither be created nor changed in combat, so the window only opens and refreshes out of combat (`pending` retries after `PLAYER_REGEN_ENABLED`). Candidates come from item class/quality/equip slot plus the "cannot be disenchanted" tooltip line; `ns.BagAPI` (from BagCleaner.lua) provides the bag helpers.
- **Dock.lua** keeps `SexyLootDB.dock[key] = { target, side, x, y }` (x/y = free position to return to). A per-frame driver re-anchors docked frames whenever EME or a resize changed their point; dragging a docked anchor in Edit Mode (hooked on `frame.Selection` in `Dock:Hook`) releases it. Dock to the anchor rectangle, not to the visible content. Buttons cannot show state (EME gives no handle to change the label), so feedback goes to chat.
- **EditMode.lua** registers every anchor with SexyEditMode (`SEM:Register`, sections via `header` specs). `ns.cfg[key]` is a table in `SexyLootDB.cfg[key]` with `ns.defaults[key]` as `__index`, so only changed values are saved and one setting set applies to all layouts. Every option here must also exist in `ns.defaults` (Core.lua).

## SexyEditMode rules

- Settings are specs (`check`, `slider`, `button`, `header`) built by the helpers at the top of EditMode.lua; getters read `ns.cfg`, setters write it and call `ns.Refresh(key)`. Position, scale and visibility (hidden, hide in combat, mouseover) are built in and stored in `SexyLootDB.frames[key]`.
- Selects work (own widgets, no Blizzard dropdown templates).

## Edit Mode preview data

`onEditMode` of every SexyEditMode entry calls `ns.SetEditMode` (Core.lua) once per change; it calls `m:Preview(active)` on every module. Each module shows sample content while editing and removes it afterwards (entries carry a `preview` flag, roll rows are tracked in `previewRows`, the loot window sets `LW.preview`). Preview rows must never match real rolls (`itemID`/`rollID` stay nil). A new window needs a `Preview` function too.

## Pitfalls

- Do not call `ClearAllPoints()`/`SetPoint()` on an anchor while it is being dragged.
- The library applies the saved position (BOTTOMLEFT) on register; `ns.CreateFrames` seeds a start position. Docked frames are re-anchored by the Dock driver.

When adding an option: add the default in `Core.lua`, add a spec in `EditMode.lua`, read `ns.cfg[key].<opt>` in the module's `ns.Apply[key]`, and document it in the README table.
